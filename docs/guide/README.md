# `docs/guide/`: the Orb engineering guide

Two kinds of document live here.

- **Subsystem guides** (`01` … `41`) explain *how a system works*, the data model, the
  request path, the guardrails, the decisions and their reasons. Read one when you need to
  understand a capability.
- **Screen maps** (`screen-map/`) explain *what is on screen and which line drew it*. Read
  one when you are looking at a pixel and need the file.

Start at the index.

---

## Start here

| | |
|---|---|
| **[00-screen-to-code.md](00-screen-to-code.md)** | **The index.** Part one routes you from a thing on screen to the screen-map file that documents it, and carries an ~80-row quick-answer table (element → component → server function). Part two is the inversion: every file and function that puts pixels on screen, with the complete list of visible elements it affects **across all screens**, including the 116 functions that drive more than one screen, which no single screen file can tell you. 237 files, 895 functions, 1,092 contribution statements. |
| **[screen-map/](screen-map/)** | **Fifteen per-screen inventories.** One file per screen, each a complete list of every visible element on that screen with the exact `file:line` that renders it, plus its states, its empty and error variants, its permission boundaries, and the things people expect to find on it that are not there. Every citation in these files was opened and read at the line it names. Each file ends with a `## Reverse map contributions` section in `path::function` → elements form; that section is the input `00-screen-to-code.md` inverts. |

## Conventions

- **Paths are repo-relative** to `/Users/samuelmorningstar/Documents/Projects/Orb`.
- **Citations are `path:line` or `` `path::function` ``.** A `::` names a function, class,
  constant, exported type, CSS selector or JSON key inside that file.
- **Screen maps document what is on screen**, including what is *not*, dead code, fields
  the server sends that nothing renders, and states that are unreachable. Those absences
  are load-bearing; do not delete them because they look like gaps.
- `_CITATION_AUDIT.md` is a work list, not a chapter. Do not link to it from a guide.
